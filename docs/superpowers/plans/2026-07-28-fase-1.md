# Fase 1 — Estabilidade do Laboratório Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Corrigir cache de placas, dados duplicados das salas e lifecycle do laboratório sem alterar a aparência ou as regras de gameplay.

**Architecture:** `RoomData.js` será a fonte imutável de nomes, limites, navegação e perfil de vento. Cada subsistema continuará dono dos seus recursos, mas `Game.destroy()` coordenará o cancelamento de callbacks e o descarte idempotente. O builder terá uma raiz própria e só liberará recursos que registrou.

**Tech Stack:** JavaScript ES modules com `// @ts-check`, Three.js, Vite, Vitest.

## Global Constraints

- Manter JavaScript; não introduzir TypeScript nem ECS.
- Preservar o visual e a ordem de interação atuais, exceto correções explícitas de lifecycle.
- Nome oficial em `x[-40,-28], z[-22,-6]`: `ALA DE MANEQUINS`.
- Nome oficial em `x[-14,14], z[-66,-46]`: `SALA DE TESTES - CONFIRMED 42`.
- Não liberar texturas cacheadas por `TextureGenerator` dentro de `LaboratoryBuilder.dispose()`.
- `destroy()` e `dispose()` precisam ser seguros quando chamados mais de uma vez.
- Não adicionar integração de IA, credenciais, telemetria externa ou dependências de runtime além das necessárias a teste.
